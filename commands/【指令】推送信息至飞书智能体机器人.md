# 推送信息至飞书智能体机器人

聊天中触发：**`/【指令】推送信息至飞书智能体机器人`**。

**仅附加本文件、不加任何文字说明时**：视为用户希望把最近一次可复用的摘要结果推送到飞书；若缺少推送内容，先简短询问；若缺少 Webhook，则按「Webhook 获取优先级」处理。

## 适用场景

- 将 MongoDB 查询结果、任务执行摘要、验证结果、告警信息推送到飞书群或飞书智能体机器人。
- 仅做**系统主动推送**；飞书 Webhook 不能反向触发 Cursor Agent，也不能接收 IM 消息回调。

## 输入要求

执行前必须具备：

1. **推送内容**：用户在对话中明确给出，或最近一次查询 / 验证 / 汇总结果可直接复用。
2. **Webhook 地址**：按「Webhook 获取优先级」获取；用户当次对话提供的 Webhook 可作为本次或本会话默认机器人。

Webhook 通常按发送凭据处理，**未经用户明确确认不得写入仓库文件、规则、脚本或提交信息**。若用户在对话中贴出 Webhook，可用于本次或本会话推送；需要长期默认时，优先配置到用户环境变量 `FEISHU_BOT_WEBHOOK_URL`。本指令内默认机器人地址已由用户确认可写入、可使用，按非敏感地址处理。

## Webhook 获取优先级

1. **用户当次对话明确提供的 Webhook**：优先使用，可视为本次任务默认机器人；若用户说明“默认用这个机器人”，在本会话后续推送中复用该 Webhook。
2. **环境变量 `FEISHU_BOT_WEBHOOK_URL`**：用户未在对话中提供 Webhook 时使用，适合个人或环境级默认机器人。
3. **指令内默认机器人**：若前两项都没有，默认使用 `https://open.feishu.cn/open-apis/bot/v2/hook/`。

## 安全要求

1. 推送前过滤敏感信息：密码、Token、连接串、手机号、邮箱、收件人、详细地址、身份证号等。
2. 数据查询结果默认只推摘要和必要业务字段；明细过多时只推 Top N，并说明总数。
3. 若推送内容来自 MongoDB MCP，遵守 `.cursor/rules/【规范】MCP 连接配置.mdc`：默认只读，修改/删除数据必须二次确认。
4. 飞书返回失败时，向用户说明 `code` / `msg`，不要重试超过一次，避免刷屏。

## PowerShell 推送模板

```powershell
$uri = $env:FEISHU_BOT_WEBHOOK_URL
if (-not $uri) {
  $uri = "https://open.feishu.cn/open-apis/bot/v2/hook/"
}

$text = @"
<这里放入已脱敏的推送内容>
"@

$body = @{
  msg_type = "text"
  content = @{
    text = $text
  }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod `
  -Uri $uri `
  -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body $body
```

## Agent 执行步骤

1. 确认推送内容来源：用户文本、最近查询结果，或需要先查询再推送。
2. 检查内容是否含敏感信息；必要时脱敏或汇总。
3. 获取 Webhook：优先使用用户当次对话明确提供的 URL；否则读取 `$env:FEISHU_BOT_WEBHOOK_URL`；仍为空时使用指令内默认机器人。
4. 发送 `msg_type=text` 消息。
5. 将飞书返回的 `code` / `msg` 告知用户；成功时简短说明已推送。

## 用户交互

- 若缺推送内容：询问“要推送哪段内容或哪次查询结果？”
- 若需临时改用其他机器人：询问“请提供本次 Webhook，或先设置 `FEISHU_BOT_WEBHOOK_URL`。”
- 若内容包含敏感字段：先说明将脱敏后推送，再执行。
